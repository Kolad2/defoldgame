# BoneHierarchy и BoneAttachment

Компонент редактора для Defold 1.14.1. По кнопке **Create** создаёт обычные
редактируемые GO-кости **под GO, к которому прикреплён компонент**.
Корневые кости становятся непосредственными детьми этого GO, остальные
сохраняют вложенность скелета. Промежуточный объект или отдельная коллекция
не создаются.

## Использование

1. Перезагрузите проект после установки расширения.
2. Добавьте **BoneHierarchy** через **Add Component** к нужному GO.
3. В **Source** выберите `.glb`, содержащий кости модели.
4. Откройте `.collection`, содержащую этот GO, и выберите его компонент
   BoneHierarchy в Outline. Это работает и для встроенного GO, и для GO,
   подключённого ссылкой на `.go`.
5. Нажмите **Create**, затем сохраните коллекцию.

Сам файл `.go` хранит компоненты, но не дочерние GO. Поэтому Create нужно
нажимать в контексте экземпляра GO в коллекции. Для GO внутри подключённой
коллекции откройте исходную коллекцию.

**Id Prefix** необязателен: пустое значение использует имя GO-владельца,
например `character/hip` или `doors/door_1`. Если ID владельца уже содержит
путь, он сохраняется: `location/doors/door_1`. Так разные экземпляры `.go`
не конфликтуют. Все кости получают префикс GO-владельца; внутренние связи
родитель–ребёнок сохраняются отдельно и не добавляют сегменты в ID.
Для ссылочного GO настройте Source и Id Prefix в исходном `.go`; в коллекции
эти поля доступны только для чтения, а кнопка Create работает для выбранного
экземпляра. Одинаковые
имена внутри одного GLB получают уникальные суффиксы; запрещённые в ID
символы заменяются на `_`.

Повторный Create при наличии совпадающих ID ничего не перезаписывает.
Для пересоздания отмените предыдущую операцию или удалите созданные кости.
Создание всей иерархии отменяется одним **Undo**.
Новый формат имён применяется при Create; существующие кости автоматически
не переименовываются.

## Что переносится

- Все уникальные joints из всех `skins` GLB, включая несколько арматур.
- Имена, родительские связи, position, quaternion rotation и scale.
- Трансформации родителей арматуры и промежуточных узлов без костей.
- Position/Rotation самого компонента; трансформация GO-владельца
  наследуется обычным способом.

Создаются кости в исходной позе GLB. Это самостоятельные GO: автоматическая
привязка к анимации `.model` и `model.get_go()` не добавляется. Меши, материалы
и обычные узлы сцены, не являющиеся joints, не создаются как GO.
Если GLB не содержит `skins/joints`, Status сообщает об отсутствии скелета.
Матрицы с shear, не представимые трансформацией GO, отклоняются до создания.

Если у `.model` включён **Create GO Bones**, движок по-прежнему создаст также
свои кости во время игры. Отключите эту настройку, если нужны только GO,
созданные редактором.

## Устройство

- `editor/src/bone_hierarchy.clj` — тип компонента, GLB-парсер и Create.
- `editor/resources/templates/template.bonehierarchy` — шаблон компонента.
- `plugins/share/bone-hierarchy-editor.jar` — готовый Bob builder.
- `source/com/dynamo/bob/pipeline/BoneHierarchyBuilder.java` — его исходник.

В игре авторский компонент компилируется в пустой `.scriptc` без callbacks.
GLB и код генератора не становятся runtime-зависимостями компонента.
Сами созданные GO собираются обычным способом. Если на GO-владельце есть
другие script-компоненты, учитывайте лимит компонентов скриптов проекта.

Плагин использует внутренний Clojure API редактора, как соседний
NavMeshConstructor; после обновления Defold может потребоваться адаптация.
Готовый JAR включён: Python, внешний GLB-конвертер и JDK для работы не нужны.

## BoneAttachment — шаблон коллекции под костью

Отдельный компонент в этом же расширении. Добавляется на GO кости (или на
любой другой GO). У каждого экземпляра свой **Source** и кнопка **Attach**.

1. После установки перезапустите Defold, чтобы загрузились новый тип и builder.
2. Откройте коллекцию локации и выберите GO кости, например `location_door_1`.
3. В Outline: ПКМ по GO → **Add Component** → **BoneAttachment**.
4. В свойствах компонента задайте **Source**:
   `/objects/locations/door/door.collection`.
5. Нажмите **Attach** и сохраните коллекцию локации.

Корневые GO из шаблона становятся непосредственными детьми кости. Вложенные
GO сохраняют связи и локальные трансформации. Например, для текущего
`door.collection` получится следующая структура:

```text
location_door_1
├── bone_attachment (компонент с Source)
└── location_door_1/door         → /objects/locations/door/door.go
    └── location_door_1/door_area → /objects/locations/door/door_area.go
```

Результат сразу виден в Outline и сцене редактора. Видимость геометрии и
коллизий определяется компонентами шаблона и обычными настройками редактора.
Для другой кости добавьте свой BoneAttachment и выберите другой Source.
На одном GO можно разместить несколько BoneAttachment, если их шаблоны
не создают совпадающих ID объектов.

ID назначаются автоматически: `<ID кости>/<ID объекта в шаблоне>`.
Например, кость `location_door_1` получает объекты `location_door_1/door`
и `location_door_1/door_area`. Родительский GO `door` не входит в ID `door_area`.
Для объектов из вложенных коллекций сохраняется их путь:
`location_door_1/handles/handle`. Промежуточный GO не добавляется.
До вставки проверяются все ID, включая адреса объектов подключённых коллекций.
При совпадении повторный Attach сообщает ошибку и ничего не вставляет.
Старые объекты не переименовываются и не перезаписываются. Переименование
кости после Attach автоматически не меняет ID уже созданных объектов.
Поле Id Prefix больше не требуется; его старое значение игнорируется.
Вся вставка отменяется одним **Undo**. Ошибки показываются в поле **Result**.

Переносятся ссылочные и встроенные GO, родительские связи, трансформации и
переопределения свойств компонентов. Вложенные коллекции также разворачиваются:
их имена входят в ID, а трансформации применяются к их корневым GO.
Position/Rotation BoneAttachment задают дополнительное смещение всей вставки.
Source читается из состояния редактора, включая несохранённые правки шаблона.

Это копирование структуры, а не живая связь с `.collection`. Ссылки на `.go`
сохраняются: изменения компонентов в исходных `.go` отражаются во всех таких
экземплярах. Изменение структуры шаблона требует повторной вставки. Скрипты,
URL и hash-свойства с именами GO автоматически не переписываются; настройте
их для новых ID. Символ `/` в ID не создаёт контекст относительных адресов
коллекции: строка `"door_area"` в скрипте не дополняется именем кости.
Используйте адрес с нужным префиксом. Настройки коллекции, включая Scale Along Z, берутся из
коллекции назначения.

Если кость — экземпляр отдельного `.go`, задайте Source в исходном `.go`,
а Attach нажмите в коллекции. Для кости внутри подключённой коллекции нужно
открыть эту коллекцию. Сам файл `.go` дочерние объекты не хранит.

Код: `editor/src/bone_attachment.clj`, шаблон:
`editor/resources/templates/template.boneattachment`, Bob builder:
`source/com/dynamo/bob/pipeline/BoneAttachmentBuilder.java` (включён в общий JAR).
В игре BoneAttachment компилируется в пустой скрипт без callbacks и зависимости
от шаблона. Созданная иерархия собирается как обычные объекты коллекции.
