## Локация и персонаж

Сцена `scripts/main.collection` использует обычные 3D-координаты: X и Z
задают положение на полу, Y — высоту. Персонаж начинает в (0, 0, 0).
Для расстановки перемещай объект `character` в плоскости XZ,
сохраняя Y = 0 и единичный масштаб.

Локация подключена через `scripts/location.go` →
`assets/locations/bar/bar.model` → `bar.glb`. Размер пола — 12 × 10,
высота стен — 3.2. В `bar.model` назначены три материала исходной модели:
пол, деревянный каркас и стены. Текстуры нового экспорта лежат в
`assets/locations/bar/textures`: `T_WoodTrim_BaseColor.png` для пола и
`room_timber_basecolor.png` для каркаса. `bar.material` использует стандартное
освещение Defold и повторение текстур по UV. Для стен назначен
`walls.material` с цветом `tint` и шейдером `solid.fp` без текстуры.
Плоскость `doors/door_1/area` служит разметкой области взаимодействия;
её отрисовка отключается в `main.script`.

Положение изометрической камеры задано в коллекции,
параметры — в `scripts/isometric.camera`. Клики преобразуются в координаты
пола без ограничения границами комнаты.

## Видимость узлов локации

`Location:set_node_visible("wall_down", false)` скрывает стену и все её меши.
В `Location.walls` хранятся восемь экземпляров `Wall`; каждый переключает
свои меши методом `Wall:set_visible(visible)`. Можно обращаться напрямую:
`location.walls.wall_down:set_visible(false)`.
Названия дочерних мешей в игровом коде не перечисляются. Имя `"walls"`
переключает все восемь групп, а имя отдельного меша (например, `"area"`)
переключает только этот меш.
Для другой локации загрузи её JSON через `sys.load_resource`, преобразуй
через `json.decode`, создай `GLBHierarchy:create(nodes)` и передай его в
`Location:create`. Класс `scripts/tools/glb_hierarchy.lua` содержит обход
дерева (`walk`), поиск узла (`find_node`) и сбор мешей под узлом (`collect_meshes`).
`Location` использует иерархию при создании стен и не хранит её у себя.
Угловые стойки в текущем GLB находятся в отдельных группах и переключаются
через эти группы. Если перенести деталь под стену в Blender, она будет
переключаться вместе с этой стеной после повторного экспорта и сборки.

Новый генератор `tools/generate_glb_hierarchy.py` извлекает только дерево
узлов из GLB и сохраняет рядом с моделью файл `{model_name}.hierarchy.json`:
`bar.glb` → `bar.hierarchy.json`. Корневые узлы собраны в список.
Узел с детьми представлен словарём `{имя: [дети]}`, конечный узел — строкой:

```json
[{"location": ["floor", {"doors": [{"door_1": ["area"]}]}]}]
```

Геометрия, трансформации, метаданные и правила видимости в этот файл не
включаются. Генератор использует сцену по умолчанию (первую, если она не
указана), сохраняет порядок детей и не меняет исходный GLB.
Узлы без имени получают имя `node_<index>`.

Перед сборкой редактор Defold и `tools/defold.ps1` запускают генератор для
всех GLB в `assets`. Нужен Python 3 в PATH. Ручной запуск:

```text
python tools/generate_glb_hierarchy.py
python tools/generate_glb_hierarchy.py assets/locations/bar/bar.glb
```

`main.script` загружает `bar.hierarchy.json` и передаёт дерево в
`Location:create`. Путь к этому JSON включён в `project.custom_resources`
файла `game.project`. Для новой локации добавь туда её `.hierarchy.json`.

При создании `Location` один раз собирает словарь `walls` с восемью ключами:
`wall_down`, `wall_right`, `wall_top`, `wall_left`, `wall_down_left`,
`wall_down_right`, `wall_top_left`, `wall_top_right`. Значение каждого ключа —
список хешей всех мешей в соответствующем поддереве. Реальные меши
определяются через `model.get_mesh_aabb`, поэтому пустые узлы в список
не попадают, а повторное упоминание одного меша не дублирует его.
У отсутствующей стены список пуст. После сбора восьми списков экземпляр
`Location` не сохраняет исходное дерево.

Меш-объекты должны иметь уникальные имена внутри одной сцены, как требуется
для однозначного переключения через Model API. У восьми групп стен также
должны быть однозначные имена. Если группа и её меш названы одинаково,
при сборе списка выбирается группа.

`Location:update_visibility(camera_direction)` автоматически переключает
группы по направлению взгляда камеры в мировых координатах (от камеры в сцену).
В `main.script` этот метод вызывается один раз из `init` при запуске локации.
При изменении направления камеры его можно вызвать повторно явно.
Направления определяются именами ключей в координатах модели:
`wall_right` — +X, `wall_left` — −X, `wall_down` — +Z, `wall_top` — −Z.
Соседние стены угла тоже определяются его именем: например,
`wall_down_left` связывает `wall_down` и `wall_left`.
При расчёте `update_visibility` угол виден, если камера оставляет видимой
хотя бы одну соседнюю стену, и скрывается только вместе с обеими.
Ручное и любое другое скрытие в этом правиле не участвует: ручное скрытие
стены не меняет видимость отдельной угловой группы. Явное скрытие самого
угла или всех стен по-прежнему действует на соответствующие группы.
Угловые группы остаются отдельно от стен в иерархии GLB.
Меши всех потомков переключаются вместе с группой.
Для новой локации используй эти имена групп в Blender; имена и количество
дочерних мешей могут быть любыми.

Перемещение и поворот объекта локации учитываются при сравнении направлений.
Методы напрямую переключают меши и не сохраняют состояние видимости.
Повторный `update_visibility` заново применяет видимость восьми групп по
направлению камеры, включая группы, ранее переключённые вручную.

## Сборка из PyCharm

В списке рядом с зелёной стрелкой выбери `Defold Build` для сборки или
`Defold Build & Run` для сборки с запуском игры. Результат сборки и ошибки
выводятся в окно Run. При ошибке сборки игра не запускается.

Конфигурации вызывают `tools/defold.ps1`, который использует Bob и Java из
установленного Defold. Открывать редактор Defold для сборки не требуется.
Результат сохраняется в `build/pycharm`, отдельно от сборки редактора.

По умолчанию установка Defold ищется по пути `../../Defold` относительно
проекта. При переносе проекта задай переменную окружения `DEFOLD_HOME`
с путём к каталогу Defold, содержащему `config` и `packages`.
Для запуска используется dmengine той же версии из локального кэша Defold.

Успешная сборка проверяет компиляцию и используемые ресурсы. Поведение игры
и ошибки, возникающие во время выполнения Lua, проверяй запуском игры.
